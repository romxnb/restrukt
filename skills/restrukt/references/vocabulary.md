# Словник

Методи не переказуються: називається ім'я, агент знає його за ключовим словом. Тут лише терміни цього плагіна і перелік імен, які він цитує.

## Процес

За таксономією Chikofsky & Cross, 1990:

| Етап | Їхній термін | Правило, що з нього випливає |
|---|---|---|
| 1 Збір | reverse engineering, design recovery | систему не змінює; піднімає висоту подання, а не переписує код іншою формою (redocumentation) |
| 2 Узгодження | — | Chat with the Maintainers, OORP |
| 3 Виконання | restructuring | за замовчуванням поведінка та сама, форма інша; окрема підтверджена зміна поведінки оновлює контракт |
| restrukt цілком | reengineering | |

## Терміни плагіна

| Термін | Означення |
|---|---|
| **точка входу** | перша callable-операція всередині чітко названої межі, яку запускає зовнішній актор або тригер; для application це dispatch leaf inbound adapter, для library/module — публічна операція з викликом з-за межі |
| **атлас** | повний перелік усіх точок входу обраного обсягу: бізнес-маршрути `Rn` і опори `In`; формат, повнота й ворота — `routes.md` |
| **маршрут** | зовнішній актор або тригер веде систему від точки входу до бізнес-результату; id `R1`, матеріально інший результат `R1x`; технічні retry й однакові transport errors окремими маршрутами не є |
| **опора** | startup, registration, migration або framework glue без самостійного бізнес-результату; id `I1`, в атласі називає маршрути, яким служить |
| **історія** | маршрут словами: Domain Storytelling, as-is, до 7 причинних кроків без ідентифікаторів у реченні; кожен крок має хвіст звірки й діаграма показує асинхронні межі та гілки. Історія **to-be** читається з хвостів «стане» |
| **крок** | одне речення історії з семантичним якорем і звіркою у хвості; id `R1.3`; на нього посилається колонка «де» |
| **семантичний якір** | функція, use case, команда, подія, policy або specification, за якою крок однозначно знаходиться в коді; може охоплювати кілька реалізаційних символів за явної межі |
| **orchestration home** | локальний для контексту handler, use case або application service, чия доменна поверхня показує причинний порядок маршруту й делегує правила глибоким модулям |
| **семантична трасованість** | відповідність історії та orchestration-коду: ті самі доменні слова, очевидні якорі, причинний порядок і явні переходи між контекстами; критерії — `routes.md` |
| **звірка** | хвіст кроку: історія проти коду; `якір@файл:рядок · =`, коли код каже те саме, або `зараз: якір n → стане: ім'я m · кошик`; Speculate about Design, OORP |
| **розбіжність** | звірка, що не дала `=`; має один із шести видів, кошиків; стає рядком плану |
| **робочий об'єкт** | те, що історія передає з кроку в крок: замовлення, товар, платіж; іменники історій наповнюють словник |
| **подія** | крок, після якого щось стало правдою: у «лапках», минулий час, Event Storming, Брандоліні; ім'я з коду через `=`, якщо є, інакше рядок кошика 2 |
| **політика** | крок, що починається сам: «коли …, тоді …», Event Storming; актором є час або зовнішня система, не програма |
| **перевірка** | крок «перевіряє …»: правило перед дією; Specification за Евансом; не стан |
| **поворотна подія** | подія, яку читає інший контекст; позначка `⇢ C2` в кінці кроку; межа контексту за Брандоліні |
| **виняток** | матеріально інший бізнес-результат: окрема історія `R1x` до 3 кроків; технічна гілка без іншого рішення актора або бізнес-стану лишається деталлю кроку |
| **гаряча точка** | файл контексту з найбільшим добутком рядків на кількість змін у git за рік; Learn from the Past, OORP; Торнгілл |
| **контекст** | Bounded Context за Евансом: маршрути зі спільною мовою, правилами та інваріантами, власником стану й причинами змін; id `C1`. Спільний файл є підказкою, поворотна подія або зміна значення слова — доказ межі |
| **підконтекст** | Modules за Евансом: маршрути контексту зі спільною мовою, правилами або власником стану, id `C1a`; зручна межа узгодження, але не обов'язково один apply |
| **кошик** | один із шести видів розбіжності між кроком і кодом: слова, події, правила, межі, склад, місце; порядок кошиків є порядком виконання |
| **пропозиція** | рядок плану: де, зараз, стане, чому, розходиться з, стан |
| **чому** | міра за connascence, Пейдж-Джонс: форма, ступінь, відстань, плюс рядки |
| **шлях** | погоджена послідовність зелених зрізів через контекст; Most Valuable First |
| **зелений зріз** | найменша зв'язана зміна одного маршруту або спільного інваріанта: оцінка до 10 хвилин роботи, максимум п'ять рядків, від зеленого швидкого контракту до зеленого; ризиковий cutover є окремим зрізом |
| **контракт** | що має лишитись правдою: наявні тести контексту і до п'яти поведінок; Characterization Test за Фезерсом |
| **джерело мови** | документ проєкту з термінами: файл контексту агента, README, `docs/`, ADR; Ubiquitous Language за Евансом, не наказ |
| **розходження** | пропоноване ім'я відрізняється від документного; показується з підставою, вирішує користувач, підтверджене править і документ |
| **сходинка** | зрілість імені за Naming as a Process, Белші: 0 немає · 1 нісенітниця · 2 чесне · 3 чесне і повне · 4 робить одне · 5 намір · 6 поняття домену; таблиця в `buckets.md` |
| **DoD** | definition of done контексту: атлас повний, orchestration семантично трасується до історій, глибокі модулі володіють правилами; ворота в `routes.md` і `apply.md` |
| **діаграма** | mermaid там, де картинка коротша за прозу: після історії, у «Контекстах» як Context Map, під кошиками як «зараз / стане»; текст канонічний, діаграма його не повторює |
