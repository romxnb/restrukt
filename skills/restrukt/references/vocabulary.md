# Словник

Нотація плагіна. Методи називаються за іменем. Етапи за Chikofsky & Cross: план — reverse engineering, код не змінюється; виконання — restructuring, поведінка та сама, форма інша; разом — reengineering.

## Нотація

| Термін | Означення |
|---|---|
| **точка входу** | перший callable усередині названої межі, який запускає зовнішній актор або тригер; для application — dispatch leaf inbound adapter, для library/module — публічна операція з викликом з-за межі |
| **атлас** | повний перелік точок входу обсягу: сценарії `Sn` і опори `In`; файл `docs/restrukt/atlas.md`; формат — `scenarios.md` |
| **сценарій** `S1` | актор або тригер веде систему від точки входу до бізнес-результату; матеріально інший результат того самого входу — `S1x` |
| **опора** `I1` | startup, registration, migration, framework glue без власного бізнес-результату; називає сценарії, яким служить; опора-реєстрація є місцем збирання |
| **контекст** `C1` | Bounded Context: сценарії зі спільною мовою, правилами, власником стану й причинами змін; підконтекст `C1a` — Module за Евансом |
| **спільний відрізок** `J1` | кроки з тими самими якорями в тому самому порядку, спільні для двох і більше сценаріїв групи; пишеться раз, сценарій-тригер закінчується `→ J1`; `scenarios.md` |
| **історія as-is** | сценарій словами, Domain Storytelling: дрібна, оцифрована, as-is; кроки без ідентифікаторів, код і звірка у хвості |
| **історія to-be** | ті самі кроки з погодженими іменами в дужках, без адрес; текст приймання для builder; при повному збігу — рядок «to-be = as-is» |
| **покриття звірки** | `N з M кроків =` у шапці сценарію: скільки кроків код уже каже так само |
| **крок** `S1.3` | одне речення історії з якорем і звіркою у хвості |
| **граф сценарію** | механічний обхід від точки входу: вузли-символи з `файл:рядок`, ребра-виклики, гілки `⎇`, нерозв'язані ребра `?`, виходи `⇥`; будується до історії, у план не потрапляє |
| **вихід** `⇥` | вузол, чий файл імпортує драйвер зі списку збирача: код тут говорить із зовнішньою системою |
| **стан вузла** | якір — входить у крок · деталь — лог, retry, мапінг, з причиною · не пояснений — код робить те, чого історія не називає; не пояснених у готовому плані немає |
| **група сценаріїв** | сценарії цільового контексту, чиї графи ділять хоч один файл; одиниця роботи сканера й одиниця паралельності |
| **семантичний якір** | функція, use case, команда, подія, policy, specification або порт, за якою крок однозначно знаходиться в коді; може охоплювати кілька символів за видимої межі |
| **звірка** | хвіст кроку: `якір@файл:рядок · =`, коли код каже те саме; інакше `зараз: якір n → стане: ім'я m · кошик · чому`; без міри connascence у «чому» хвіст `стане` не пишеться |
| **кошик** | вид розбіжності між кроком і кодом: слова, події, правила, межі, склад, місце, виходи; `buckets.md` |
| **пропозиція** `C1.4` | рядок плану: де, зараз, стане, чому, розходиться з, стан; дочірні рядки `C1.4a`, `C1.4b`; id стабільний між зборами |
| **чому** | connascence: форма, ступінь, відстань, рядки |
| **сходинка** `n` | зрілість імені за Naming as a Process, 0–6; таблиця в `buckets.md` |
| **чесне і повне ім'я** | сходинка 3 одним реченням: що символ робить насправді, усе через «і»; підстава для нового імені й лінія розрізу для кошика склад |
| **антипатерн** `B.2` | Linguistic Antipattern за Арнаудовою, групи A–F: ім'я обіцяє не те, що тіло робить; ставить сходинку зараз не вище 2 |
| **таблиця імен** | секція контексту: зараз, антипатерн, чесне і повне ім'я, стане, число «і»; `buckets.md` |
| **гаряча точка** | файл контексту з найбільшим добутком рядків на кількість змін за рік |
| **orchestration home** | локальний для контексту handler, use case або application service, чия поверхня читається як історія; канонічно use case, interactor; `scenarios.md` |
| **зовнішня система** | усе, з чим код говорить протоколом, не словами домену: база, мережа, файли, годинник, framework UI; driven actor за Кокберном |
| **порт** | інтерфейс до зовнішньої системи доменними словами; driven port |
| **адаптер** | реалізація порту для конкретного драйвера; driven adapter |
| **місце збирання** | де порти з'єднують з адаптерами: `main`, registration, наявний контейнер; composition root; опора `In` |
| **семантична трасованість** | історія і orchestration-код збігаються словами, якорями, порядком і переходами між контекстами; ворота в `scenarios.md` |
| **контракт** | наявні тести контексту і до п'яти поведінок, що мають лишитись правдою; Characterization Test |
| **зелений зріз** | найменша зв'язана зміна одного сценарію або інваріанта, до 5 рядків, від зеленого контракту до зеленого; `apply.md` |
| **рецепт зрізу** | упорядкований список рухів зрізу: рух за Фаулером, адреса, нове ім'я або сигнатура, файл призначення, викликачі, тест; кроїльник пише, builder виконує; `apply.md` |
| **шлях** | погоджена послідовність зрізів через контекст; Most Valuable First |
| **джерело мови** | документ проєкту з термінами: `CLAUDE.md`, README, `docs/`, ADR; кандидат, не наказ |
| **розходиться з** | пропоноване ім'я відрізняється від документного; вирішує користувач, підтверджене править і документ |
| **стан** | порожньо · `підтвердити` · `так` · `ні` · `змінено: …` · `виконано` · `пропущено: …` · `знято: …` · `без відповіді` |

## Рівні плану

Читач визначає файл. Нижчий рівень посилається на вищий id і адресою, не переказом.

| Рівень | Читач | Що | Де |
|---|---|---|---|
| 1 рішення | користувач | шапка, контексти з картою, питання, пропозиції зі станами, імена, шляхи | `docs/restrukt/plan.md`, до 200 рядків |
| 2 приймання | builder | to-be, спільні відрізки, контракт | `docs/restrukt/stories/Cn.md`, верх |
| 3 доказ | той, хто сумнівається | as-is з якорями, покриття, діаграми, деталі графа, відповіді на словник | `docs/restrukt/stories/Cn.md`, низ |
| 4 механіка | ніхто після плану | графи, збір, атласи контекстів | тимчасові файли, видаляються |

Атлас — `docs/restrukt/atlas.md`, рівень 2: користувачеві досить чисел і контекстів у шапці.

## Граматика історії

Event Storming у реченнях Domain Storytelling:

| Елемент | Запис |
|---|---|
| подія | «…» у минулому часі; ім'я з коду через `=`, інакше кошик 2 |
| політика | «коли …, тоді …»; актором є час або зовнішня система |
| перевірка | «перевіряє …»; правило перед дією, Specification |
| зовнішня система | крок називає її словами домену: «магазин списує оплату»; у хвості порт, якщо є: `(через PaymentPort)`, інакше кошик 7 |
| поворотна подія | `⇢ C2` у кінці кроку; лише між контекстами верхнього рівня |
| спільний відрізок | `→ J1` у кінці останнього власного кроку сценарію-тригера |
| робочий об'єкт | іменник, що йде з кроку в крок; наповнює словник |
| виняток | матеріально інший результат: окрема історія `S1x` до 3 кроків; технічна гілка лишається деталлю кроку |
