# Етап 2 · Узгодження

**Chat with the Maintainers** через інструмент `AskUserQuestion`, серіями. Один виклик несе до 4 питань, кожне до 4 варіантів; «Other» дає користувачеві вписати своє. Код не читається, сканери не запускаються.

**Питання ставиться лише там, де відповідь міняє роботу.** Рядок з одним розумним рухом не питається: він іде за шляхом як `так` і стоїть у плані для читання. Три види питань, інших немає:

| Вид | Скільки | Питання | Варіанти |
|---|---|---|---|
| історії | одне, перше | «Історії тримаються?» | `Усі тримаються (Recommended)` · `Не всі: скажу, які` з текстом. Хибна історія — рядки з її кроками знімаються, сканер контексту перепроходить лише цей маршрут із поправкою користувача в дорученні, серія триває після повернення |
| шлях | одне, лише коли рядків більше за 30 | «Який шлях беремо?» | A · B · C з описом «що входить, рядків». До 30 рядків шлях один, «усе», і не питається |
| рішення про поведінку | питання сканерів `Qn` обраного шляху | наслідок для продукту одним реченням: «Коли банк не відповів, важливіше відпустити замовлення на склад чи не відвантажити неоплачене?» | `a · b` наслідками; `файл:рядок` лише в кінці description |
| ім'я | одне на рядок кошика **слова** обраного шляху, крім рядків «видалити» і імен у модулі з перебудовою | крок історії, де ця річ діє, дослівно, без коду: «R1.2: коли замовлення оформлено, тоді магазин резервує товар на складі. Як назвати цей крок у коді?» | слово з документа, якщо є · слово сканера · третє по суті; description одним реченням, чому саме це |

Кошики події, правила, межі, склад, місце не питаються: їхні рядки стають `так` разом зі шляхом. Режим складу, ремонт чи перебудова, уже є питанням сканера.

## Форма

Header до 12 знаків: id рядка. У question і label код не пишеться: ні ідентифікаторів, ні `файл:рядок`, ні стрілок `зараз → стане`; ім'я-кандидат у label є єдиним винятком. Description до двох речень. Один контекст за серію, до 4 питань у виклику.

Документ є кандидатом, не вироком: слово з джерела мови стоїть варіантом поруч зі словом сканера, і обране інше слово править документ разом із кодом. Переконувати можна одним реченням у description і один раз; далі відповідь остаточна.

## Перед першою серією

У чат, з файлу: секція «Історії» дослівно, з діаграмами, потім рядок чисел із шапки, таблиця «Контексти» з Context Map і «Між контекстами». Історії є моделлю, яку користувач перевіряє перед кандидатами, Domain Storytelling; хвости «стане» показують, куди йде код. Більше нічого, деталі несуть питання.

## Запис

Після **кожного** виклику оркестратор править `docs/restrukt/plan.md`, до наступного виклику:

| Відповідь | Стан у плані |
|---|---|
| шлях, або історії при рядках до 30 | рядки шляху → `так`, крім рядків кошика слова і рядків, що залежать від `Qn`: вони чекають своїх питань |
| на `Qn` | колонка «відповідь»; залежні рядки дістають обране |
| ім'я з документа | «стане» бере його, «розходиться з» → `= файл:рядок`, → `так` |
| ім'я сканера або третє | → `так`; якщо документ мав інше слово, «розходиться з» лишається: документ правиться разом |
| Other з текстом | → `змінено: <текст>`, «стане» перезаписане |
| остання: `Виконуй усе узгоджене` · `Виконуй лише Cn` · `Ще подивлюся план` | запуск або зупинка; стани збережені, `/restrukt:apply` покаже, що без відповіді |

## Вихід

`Виконуй…` → `/restrukt:apply` з обраними контекстами. Рядок без стану не виконується, у лог іде як `без відповіді`.
