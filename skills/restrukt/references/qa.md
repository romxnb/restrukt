# Етап 2 · Узгодження

Chat with the Maintainers через `AskUserQuestion`, серіями: один виклик — до 4 питань, кожне до 4 варіантів; «Other» дає вписати своє. Код не читається, сканери не запускаються.

**Питання ставиться лише там, де відповідь міняє роботу.** Низькоризиковий рядок з одним розумним рухом іде за шляхом як `так`. **Ризиковий** рядок — зміна спостережуваної поведінки, видалення, публічний API, формат збережених даних, межа контексту, перебудова модуля, новий порт на межі з зовнішньою системою, яку міряє лише апаратний харнес — має стан `підтвердити` і схвалюється лише окремим питанням ризику. П'ять видів питань:

| Вид | Скільки | Питання | Варіанти |
|---|---|---|---|
| атлас та історії | одне, перше | «Атлас повний, а деталізовані історії тримаються?» — питання про as-is: чи так воно працює сьогодні | `Так (Recommended)` · `Ні: скажу, чого бракує або що хибне`. Пропущена точка входу додається до атласу; хибний сценарій сканер перепроходить з поправкою користувача |
| шлях | одне, коли є секція «Шляхи» | «Який шлях беремо?» | A · B · C з сценаріями, кількістю зрізів і рядків |
| рішення про поведінку | питання сканерів `Qn` обраного шляху | наслідок для продукту одним реченням: «Коли банк не відповів, важливіше відпустити замовлення на склад чи не відвантажити неоплачене?» | `a · b` наслідками; `файл:рядок` лише в кінці description |
| ім'я | одне на рядок кошика слова або виходи обраного шляху, крім «видалити» і імен у модулі з перебудовою | крок історії дослівно: «S1.2: коли замовлення оформлено, тоді магазин резервує товар на складі. Як назвати цей крок у коді?» | слово з документа, якщо є · слово сканера · третє по суті; у description — чесне і повне ім'я з таблиці імен: що воно робить насправді, і група антипатерна, якщо є |
| ризик | одне на контекст, якщо в шляху є `підтвердити` | «Виконувати ризикові рядки C1.4, C1.7?»; у description наслідок кожного id | `Усі перелічені` · `Жодного` · `Скажу, які`; без рекомендованого |

## Форма

Header до 12 знаків: id рядка. У question і label — жодного коду, ідентифікаторів чи `файл:рядок`; ім'я-кандидат у label є єдиним винятком. Description до двох речень. Один контекст за серію. Документ — кандидат, не вирок: слово з джерела мови стоїть варіантом поруч зі словом сканера. Переконувати — одним реченням у description, один раз.

## Перед першою серією

У чат — `plan.md` дослівно: це рівень рішень, до 200 рядків. Історії не переказуються: на кожен контекст один рядок «історії: `docs/restrukt/stories/Cn.md`, N сценаріїв, покриття N з M», і історія to-be з файлу на прохання або коли питання її стосується. Атлас — рядком чисел із шапки.

## Запис

Після кожного виклику оркестратор править `docs/restrukt/plan.md`, до наступного:

| Відповідь | Стан у плані |
|---|---|
| шлях, або атлас та історії при одному зрізі | рядки шляху → `так`, крім рядків кошика слова, залежних від `Qn` і `підтвердити`: вони чекають своїх питань |
| на `Qn` | колонка «відповідь»; залежні рядки дістають обране |
| ім'я з документа | «стане» бере його, «розходиться з» → `= файл:рядок`, → `так`; ризиковий лишається `підтвердити` |
| ім'я сканера або третє | → `так`; ризиковий лишається `підтвердити`; якщо документ мав інше слово, «розходиться з» лишається: документ правиться разом |
| ризик: усі | перелічені `підтвердити` → `так`; `підтвердити · змінено: …` → `змінено: …` |
| ризик: жодного | перелічені → `ні` |
| ризик: вибрані id | вибрані → `так` або збережене `змінено: …`, решта → `ні` |
| Other з текстом | → `змінено: <текст>`, «стане» перезаписане; ризиковий → `підтвердити · змінено: <текст>` |
| остання: `Виконуй усе узгоджене` · `Виконуй лише Cn` · `Ще подивлюся план` | запуск або зупинка; стани збережені |

Відповідь, що міняє «стане» або дає рядку `ні`, править і відповідний крок історії to-be у `stories/Cn.md`: інакше приймання спирається на текст, який уже не погоджений.

`Виконуй…` → `/restrukt:apply` з обраними контекстами. Рядок без стану не виконується, у лог іде як `без відповіді`.
