# Етап 2 · Узгодження

**Chat with the Maintainers** через інструмент `AskUserQuestion`, серіями. Один виклик несе до 4 питань, кожне до 4 варіантів; «Other» дає користувачеві вписати своє. Код не читається, сканери не запускаються.

**Питання ставиться лише там, де відповідь міняє роботу.** Низькоризиковий рядок з одним розумним рухом не питається: він іде за шляхом як `так` і стоїть у плані для читання. Рядок зі станом `підтвердити` автоматично не схвалюється. П'ять видів питань, інших немає:

| Вид | Скільки | Питання | Варіанти |
|---|---|---|---|
| атлас та історії | одне, перше | «Атлас повний, а деталізовані історії тримаються?» | `Так (Recommended)` · `Ні: скажу, чого бракує або що хибне`. Пропущена точка входу додається до атласу; хибний маршрут сканер перепроходить лише з поправкою користувача |
| шлях | одне, коли план потребує кількох зелених зрізів | «Який шлях беремо?» | A · B · C з описом маршрутів, кількості зрізів і рядків. Один зріз до 5 рядків — питання немає |
| рішення про поведінку | питання сканерів `Qn` обраного шляху | наслідок для продукту одним реченням: «Коли банк не відповів, важливіше відпустити замовлення на склад чи не відвантажити неоплачене?» | `a · b` наслідками; `файл:рядок` лише в кінці description |
| ім'я | одне на рядок кошика **слова** обраного шляху, крім рядків «видалити» і імен у модулі з перебудовою | крок історії, де ця річ діє, дослівно, без коду: «R1.2: коли замовлення оформлено, тоді магазин резервує товар на складі. Як назвати цей крок у коді?» | слово з документа, якщо є · слово сканера · третє по суті; description одним реченням, чому саме це |
| ризик | одне на контекст, якщо в обраному шляху є `підтвердити` | «Виконувати ризикові рядки C1.4, C1.7?»; у description коротко наслідок кожного id | `Усі перелічені` · `Жодного` · `Скажу, які`; рекомендованого варіанта немає |

Кошики події, правила, межі, склад, місце без стану `підтвердити` стають `так` разом зі шляхом. Ризиковими є зміна спостережуваної поведінки, видалення, публічний API, формат збережених даних, межа контексту і перебудова модуля; вони проходять через одне питання ризику на контекст.

## Форма

Header до 12 знаків: id рядка. У question і label код не пишеться: ні ідентифікаторів, ні `файл:рядок`, ні стрілок `зараз → стане`; ім'я-кандидат у label є єдиним винятком. Description до двох речень. Один контекст за серію, до 4 питань у виклику.

Документ є кандидатом, не вироком: слово з джерела мови стоїть варіантом поруч зі словом сканера, і обране інше слово править документ разом із кодом. Переконувати можна одним реченням у description і один раз; далі відповідь остаточна.

## Перед першою серією

У чат, з файлу: «Атлас маршрутів», потім «Історії» дослівно з діаграмами, рядок чисел із шапки, «Контексти» з Context Map і «Між контекстами». Користувач спершу перевіряє повноту поведінки й модель Domain Storytelling; хвости «стане» показують, куди йде код. Більше нічого, деталі несуть питання.

## Запис

Після **кожного** виклику оркестратор править `docs/restrukt/plan.md`, до наступного виклику:

| Відповідь | Стан у плані |
|---|---|
| шлях, або атлас та історії при одному зрізі | рядки шляху → `так`, крім рядків кошика слова, залежних від `Qn` і рядків `підтвердити`: вони чекають своїх питань |
| на `Qn` | колонка «відповідь»; залежні рядки дістають обране |
| ім'я з документа | «стане» бере його, «розходиться з» → `= файл:рядок`, → `так`; ризиковий рядок лишається `підтвердити` |
| ім'я сканера або третє | → `так`; ризиковий рядок лишається `підтвердити`; якщо документ мав інше слово, «розходиться з» лишається: документ правиться разом |
| ризик: усі | перелічені рядки `підтвердити` → `так`; `підтвердити · змінено: …` → `змінено: …` |
| ризик: жодного | перелічені рядки `підтвердити` → `ні` |
| ризик: вибрані id | вибрані → `так` або збережене `змінено: …`, решта → `ні` |
| Other з текстом | → `змінено: <текст>`, «стане» перезаписане; ризиковий рядок → `підтвердити · змінено: <текст>` |
| остання: `Виконуй усе узгоджене` · `Виконуй лише Cn` · `Ще подивлюся план` | запуск або зупинка; стани збережені, `/restrukt:apply` покаже, що без відповіді |

## Вихід

`Виконуй…` → `/restrukt:apply` з обраними контекстами. Рядок без стану не виконується, у лог іде як `без відповіді`.
