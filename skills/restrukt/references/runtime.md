# Виконання й делегування

Основний агент володіє загальним планом, розуміє код і перевіряє інтеграцію. Типово працюй сам. Цей довідник дозволяє необов'язкове делегування за умовами нижче; обов'язкового запуску помічників немає.

## Коли залучати помічника

Усі умови мають виконуватися:

- є цілісний результат: дослідити відокремлений модуль, реалізувати частину за визначеним контрактом або перевірити конкретний ризик;
- основний агент має іншу корисну роботу на час виконання;
- входи й залежності достатньо визначені; помічник не мусить повторно досліджувати весь застосунок;
- ділянки запису не перетинаються з іншою поточною роботою, включно з тестами, конфігурацією й спільними документами;
- очікуваний виграш виправдовує передачу контексту та перевірку результату.

Пошук файлів, збирання таблиці чи передача вже готового тексту самі по собі не потребують агента. Типово не більше двох помічників одночасно й не більше місткості середовища. Наявний спільний файл означає залежність: спочатку узгодь інтерфейс, потім виконуй частини послідовно або розділи власність на файли.

## Доручення й повернення

Передай мету, потрібну поведінку, цільовий інтерфейс, дозволені файли, перевірку, відомі факти й обмеження. Роль — [restrukt-worker](../../../agents/restrukt-worker.md). Передавай абсолютні шляхи та лише методичну інструкцію поточного кроку; весь каталог помічнику не потрібний. Даючи дослідження чи перевірку, явно вкажи режим без правок.

Помічник сам обирає реалізацію в межах контракту, читає потрібний код і перевіряє результат. Зміну спільного інтерфейсу, поведінки або чужого файла повертає основному агенту як конкретну залежність. Загальний план і журнал редагує лише основний агент.

Повернення стисло: результат, змінені файли або адреси доказів, виконані перевірки, невідоме. Основний агент переглядає diff, перевіряє сумісність і інтеграцію, тоді оновлює стан. Після невдалого доручення допускається одне уточнення; далі основний агент бере частину собі або фіксує реальну перешкоду.

## Claude Code і Codex

У Claude Code використай наявний засіб запуску агентів із роллю `restrukt-worker`. Модель успадковує налаштування середовища. У Codex, якщо доступні collaboration tools, використовуй `spawn_agent` із `fork_turns: "none"`, самодостатнім дорученням і без примусової заміни моделі; продовження — `followup_task`. Якщо потрібного засобу немає, виконай частину сам.

Очікуй завершення доступним засобом очікування, враховуй фактичний результат і припиняй залежну роботу при помилці. Нові користувацькі задачі в бічній панелі для внутрішніх частин не створюй. Явний вибір моделі користувачем має пріоритет; неперевірених припущень про найдешевшу чи найсильнішу модель не роби.

## Контроль витрат

Досліджуй код пакетами навколо потрібного сценарію. Повторне читання виправдане зміною коду, новою залежністю або перевіркою висновку. Не змушуй агента пам'ятати файл назавжди й не перечитуй увесь репозиторій при кожному продовженні.

Зберігай у плані висновки, адреси доказів, чергу й невідоме; у журналі — результати. Перед вичерпанням доступного бюджету залишай ресурс на перевірку поточної частини й збереження точки продовження. Бюджет спільний для всіх агентів. Коли середовище не показує токени або час, не вигадуй цифр і не заявляй виміряної економії.
