# Профілі моделей

Єдине місце, де роль зіставляється з моделлю. Решта файлів називає лише профіль.

## Три профілі

| Профіль | Ролі | Що робить | Чого не робить |
|---|---|---|---|
| механіка | collector, mapper, checker | ґреп, рядки атласу, графи викликів, звірка готового тексту за адресами | історії, межі, імена, порти, порівняльне судження над кодом |
| судження | scanner, cutter | читає файли групи сам, пише історії й рядки плану, рецепт і вердикт | механічний збір, який дешевша модель робить так само |
| виконання | builder | рухи готового рецепта дослівно, контракт до і після, лог | рішення, яких рецепт не містить |
| сесійна | оркестратор | запуск, злиття `cat`, показ плану, запис відповідей | читання коду |

## Зіставлення за runtime

| Профіль | Claude Code `model · effort` | Codex `model · reasoning` |
|---|---|---|
| механіка | `haiku · low` | `gpt-5.6-luna · low` |
| судження | `opus · medium` | `gpt-5-luna · Xhigh` |
| виконання | `sonnet · low` | `gpt-5.6-terra · low` |

Назви для Codex беруться зі schema `spawn_agent` поточної сесії. Названої моделі немає — механіка бере найдешевшу доступну agentic-модель на `low`, судження — найсильнішу на `medium`, виконання — найдешевшу, здатну на надійне редагування, на `low`.

## Де живе зіставлення

- Claude Code читає `model` і `effort` із frontmatter `agents/restrukt-*.md`; ці два рядки є копією таблиці вище, іншого механізму runtime не має.
- Codex читає цю таблицю через `references/codex.md` і передає модель у `spawn_agent`.

Зміна моделі робиться тут, потім у frontmatter. Перевірка збігу одним ґрепом:

```sh
grep -H '^model:\|^effort:' agents/restrukt-*.md
```

## Чому так

Виміряно на реальному плані. Дешева модель тримає нотацію, адреси й правила на готовому тексті, але не тримає судження над кодом. Середня губить порівняльні знахідки. Сильна на `medium` дає знахідки рівня сесійної моделі, на `low` губить одну. Ціну сканера робить обсяг файлів, що входить у його контекст, не глибина думання, тому сканер читає файли сам, а не з рук дешевої моделі.
