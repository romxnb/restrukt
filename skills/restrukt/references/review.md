# Adversarial review

Відкрий після інтеграції, перед оголошенням обсягу готовим. Рецензуй результат як опонент: шукай докази, що зміна стала локальною лише на словах.

Перевір: evolutionary trap (стара структура лишилася головним маршрутом); folder trap (теки повторюють технічні шари); shallow abstractions (інтерфейси лише переадресовують виклики); naming convergence (один концепт має кілька назв); alternatives (немає двох варіантів із trade-offs); overengineering (шари не приховують варіативності); deletion (старий шлях, міст, дубльований термін і мертвий код залишилися).

Для кожної знахідки запиши доказ, ризик і дію. Порушення acceptance criteria повертає частину в чергу. Завершення дозволене лише після повторної перевірки головних сценаріїв і повного diff.
