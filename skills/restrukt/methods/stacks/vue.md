# Vue

Коли: `package.json` вимагає `vue`. Конкретизує тактичний дизайн для Vue 3 з TypeScript. Прийнятий у проєкті інший прийом — наприклад, Pinia для всього стану сторінок — важливіший за цей довідник.

| Потреба | Роби | Не роби |
|---|---|---|
| сторінка | компонент у теці сторінок з `<script setup lang="ts">` і локальним станом у `ref` та `computed` | глобальний стан для даних однієї сторінки |
| дочірній компонент | коли частина має власний стан і події, повторюється або сторінка вже не читається з одного-двох екранів | компонент на кожен блок розмітки |
| запит до API | функції модуля API ресурсу через клієнт проєкту, типи відповіді поруч | `fetch` у компоненті; заголовки, зібрані вручну; `any` |
| спільна логіка | composable, коли той самий стан із поведінкою потрібен кільком компонентам; store — коли стан спільний між сторінками | composable чи store для одного компонента |
| стан запиту | завантаження, помилка з `role="alert"`, неактивна кнопка під час надсилання; після зміни — перечитати дані з сервера | ручне оновлення копії списку, що розходиться із сервером |
| похідне значення | `computed` | `watch`, що записує в інший `ref` |
| форматування | спільна функція проєкту | друга копія форматування дат чи чисел |
| тести | Vitest і Vue Test Utils: змонтуй сторінку, підміни модуль API, перевір текст і дії користувача | перевірка внутрішнього стану компонента; знімки розмітки |

Сторінка, що читає, змінює й перечитує дані:

```vue
<script setup lang="ts">
const invoices = ref<Invoice[]>([])
const error = ref('')

async function load() {
  try {
    invoices.value = await fetchInvoices()
  } catch (e) {
    error.value = (e as Error).message
  }
}

async function voidInvoice(invoice: Invoice) {
  error.value = ''
  try {
    await voidInvoiceRequest(invoice.id)
    await load()
  } catch (e) {
    error.value = (e as Error).message
  }
}

onMounted(load)
</script>
```
