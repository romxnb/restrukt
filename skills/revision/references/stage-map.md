# Огляд

Дає точки входу, сценарії і вибір першого сценарію. Два шляхи за обсягом.

## Скорочений огляд: до 50 файлів

Оркестратор робить сам, без помічників. Чотири розвідники на двадцяти файлах читають їх вісімдесят разів і не знаходять нічого понад те, що знаходить один ґреп.

1. Порахуй файли в обсязі.
2. Пройди одинадцять видів точок входу з `vocabulary.md` ґрепом. Підказки:

| Вид | За чим шукати |
|---|---|
| HTTP, GraphQL, RPC, вебхук | декоратори й реєстрації роутів, `@Get`, `router.`, `resolver`, `handler` |
| CLI | `main`, парсер аргументів, `command` |
| подія інтерфейсу | `onClick`, `action`, `Button(`, `.onChange` |
| підписник, консюмер черги | `subscribe`, `addObserver`, `Listener`, `consume`, `sink` |
| запланована задача | `Timer`, `cron`, `schedule` |
| хук старту | `init`, `applicationDidFinishLaunching`, `main.ts`, міграції |
| публічний експорт | `public`, `export`, індексні файли |

3. Кожній точці — вид і `файл:рядок`. Вид, якого немає, теж записується з поміткою «не виявлено».
4. Згрупуй точки в сценарії: **актор + дієслово + результат**. Точка без сценарію — інфраструктурна.
5. Обери перший сценарій: названий користувачем, інакше з найбільшою кількістю точок входу.
6. Для обраного сценарію обери маршрут: той, що веде до запису у сховище або зовнішнього виклику.
7. Знайди джерела мови, не читаючи їх: `CLAUDE.md`, `AGENTS.md`, `README*`, `CONTRIBUTING*`, `docs/**/*.md`, ADR, `.cursorrules`, `_glossary.md` з минулого прогону. Кожному — шлях, що задає (терміни чи правила імен, з заголовків), рядків. Немає жодного — «не виявлено».
8. Запиши `docs/revision/_map.md` за шаблоном. Ребра, висоти сценаріїв і повний словник тут не потрібні.

## Повний огляд: понад 50 файлів або `/restrukt:map`

Точки входу шукають `revision-scout`, по групі видів на кожного, до чотирьох. Далі оркестратор:

**Висота сценарію.** Сценарій рівня моря за Кокберном виконує три умови: починається з одної зовнішньої події, дає результат, який актор назве, лишає сутності у станах із назвою в домені. Виконались усі три — сценарій. Усі, крім першої — хмара, розкладається на сценарії. Не виконалась друга або третя — фрагмент, не сценарій.

**Ребра** шукаються лише навколо обраного сценарію, трьох типів: спільний код, спільний стан, спільне слово. Для спільного слова записується, одне в нього значення чи два. Це спостереження, не привід зводити.

**Робочий набір** — обраний сценарій плюс ті, з ким він ділить код або стан. У покроковій команді його обирає користувач.

**Словник** `_glossary.md` за шаблоном: терміни цього коду, не терміни методу; одне речення на термін; слово з двома значеннями позначене ⚠️. Колонку «сходинка» лишає порожньою: її заповнює судження.

## Ворота виходу

1. Кожен вид перевірено, зокрема відсутні.
2. Кожна точка має вид, `файл:рядок` і сценарій або позначку «інфраструктурна».
3. Кожен сценарій сформульовано як актор + дієслово + результат.
4. Перший сценарій і маршрут обрано, причина записана.
5. Джерела мови перелічені або стоїть «не виявлено».
6. Кожне речення описує те, що є.
