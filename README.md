# restrukt

Перебудовує застосунок у код, який людина може зрозуміти й підтримувати: видимі сценарії, визначені власники правил і стану, цілісні модулі, перевірена поведінка.

## Використання

| Задача | Claude Code | Codex |
|---|---|---|
| Створити план | `/restrukt:plan [обсяг]` | `$restrukt plan [обсяг]` |
| Реалізувати одну задачу | `/restrukt:apply [план] [задача]` | `$restrukt apply [план] [задача]` |
| Перевірити задум | `/restrukt:review plan` | `$restrukt review plan` |
| Перевірити зібрану систему | `/restrukt:review` | `$restrukt review` |
| Доопрацювати конкретний недолік | `/restrukt:refine [names або coupling] [обсяг]` | `$restrukt refine [names або coupling] [обсяг]` |
| Подивитися стан | `/restrukt:status` | `$restrukt status` |

Без режиму `$restrukt [обсяг]` створює план. Обсяг — застосунок, тека або модуль; без нього використовується розмова чи поточний проєкт. Кілька рівноправних застосунків потребують уточнення.

## Workflow

1. **Планувальник створює план.** Відновлює сценарії та неявні правила, відділяє факти від гіпотез, незалежно проєктує модулі й гарантії. Пов'язує потрібний результат із правилом, рішенням, задачею та перевіркою. Кожна задача має контракт для нового виконавця. План перевіряється на сценаріях і залежностях; продуктовий код і тести не змінюються.
2. **Новий агент виконує одну задачу через apply.** Звіряє план з актуальним кодом, захищає поведінку перевіркою, реалізує й підключає результат, перевіряє використання, узгоджує назви та прибирає замінене. Передає стан наступному агенту й завершує виклик. Без назви продовжує незавершену задачу або бере першу доступну; незавершені залежності автоматично не виконує.
3. **Зведення входить у задачу плану.** Після інтеграції узгоджуються рішення, словник, дерево й залежності, видаляються зайві шари, старі поняття та мости.
4. **Новий рев'ювер перевіряє ціле.** Читає фактичний код і загальний diff, перевіряє наскрізну поведінку та взаємодії між задачами. Реалізацію не змінює; доведені знахідки повертає в задачі для `apply`. Після виправлень перевіряється змінене та його вплив. Готовність усіх задач і приймання цілого — окремі стани.

Для незалежного перегляду відкрий новий чат і виклич `review`; цей режим сам не створює агента. Так само можна виконати `review plan` до реалізації. Автор може зробити самоперевірку з явним позначенням цього факту. Обов'язкових хвиль помічників немає.

## План і самостійність

Робоча пам'ять — `docs/restrukt/<назва>/plan.md` та `log.md`: кожен обсяг має власну теку, тож кілька планів співіснують. Інші режими обирають план за назвою теки, обсягом або задачею; за неоднозначності уточнюють. План зберігає правила, рішення, контракти задач, залежності й стан. Журнал — фактичні результати та перевірки. Спільне знання описується один раз; задача посилається на потрібний контекст.

Поведінка, сумісність і явні обмеження користувача задають рамки. Агент може переглянути власне архітектурне рішення за новими доказами, оновивши залежні задачі; типи, функції й розташування файлів обирає самостійно. Погодження плану не фіксує всі деталі. Питання потрібне для невідомого продуктового результату чи дії поза дозволом. Коміт, публікація та міграція реальних даних потребують доручення.

Довідник режиму визначає порядок роботи, методики — прийоми й винятки, критерії — приймання, шаблони — пам'ять. Агент читає потрібне на поточному кроці. Тактичний дизайн застосовується під час написання коду й перевірки його використання.

## Вузькі доопрацювання

`refine names` застосовує Naming as a Process; `refine coupling` — connascence. Один виклик усуває один доведений недолік у заданому обсязі зі збереженням поведінки. Без наявного плану робочих документів не створює. Нова архітектура повертається як структурна задача; інші режими й фокуси не запускаються автоматично.

## Результат і витрати

Відповідь показує результат, де читати сценарій, суттєві рішення, фактичні перевірки, залишок і наступний крок; деталі — посиланнями. Незавершене та неперевірене називається прямо.

Агент досліджує код поступово, зберігає докази й не повторює підтверджений аналіз без причини. Помічники необов'язкові та отримують обмежені доручення. Бюджет включає аналіз, реалізацію, перевірку й усіх помічників. Виміряну економію, час і токени можна повідомляти лише за наявності даних.

## Встановлення

Claude Code:

```text
/plugin marketplace add romxnb/restrukt
/plugin install restrukt@restrukt
```

Codex, із кореня локального клону:

```sh
codex plugin marketplace add ./
```

У Plugins Directory вибери marketplace `restrukt` і встанови плагін.
